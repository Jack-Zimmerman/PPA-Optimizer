# Session 2 — verification gate, dev agents, and the iteration loop

Goal: nothing generated by an LLM reaches the OpenROAD flow unless it passes tests built from the spec, and a loop that uses the flow's reports to improve a design. Test status at the end: `.venv/bin/python -m pytest tests -q` gives 54 passed (about 50 s with Docker running).

## What changed along the way

The first version of the gate compared each candidate to a golden reference RTL in lock-step. That was replaced mid-session: the original RTL is itself generated by Claude from a spec, so **there is no baseline**. The oracle is now a test suite written from the spec alone, and the suite itself is checked before it is trusted.

## The pipeline

```
loose idea ──spec-resolver──> spec with port table ──┬─ rtl-author ──> RTL
 (optional)                                          └─ test-author ──> suites/<name>/   (never sees RTL)
                                                                              │
RTL ──> make qualify (is the suite trustworthy?) ──> candidates ──> lint ──> port check ──> suite ──> OpenROAD flow
                                                                                              ▲
                                                       make iterate: rewrites + flow knobs, keep the best
```

## 1. Verification gate — `ppa_opt/verify/`

| File | Role |
|---|---|
| `suite.py` | Suite contract and loader (`PORTS`, `CLOCK`, `RESET`, `Model`, `COVER`, optional `DIRECTED`/`RANDOM`/`N_RANDOM`). `check_ports` compares spec ports to RTL ports. |
| `SUITE_FORMAT.md` | The rules the test author follows: work from the spec only, model returns `None` for unspecified outputs, cover every table row and corner. |
| `interface.py` | Reads RTL ports (name, direction, width) from Verilator's JSON dump, no C++ build. |
| `stimulus.py` | Reset, the suite's directed vectors, an automatic corner sweep, exhaustive when 16 input bits or fewer, then seeded random with occasional mid-run resets. |
| `cocotb_test.py` | The cocotb body: drives the DUT, checks every output against the model each cycle, counts cover-point hits. Has a 600 s wall budget (checked between cycles). |
| `bench.py` | Builds `tb_top` (DUT plus the suite's SVA module) in Verilator with `--assert --coverage-line --coverage-toggle`, runs it, parses line/toggle coverage of the RTL files from `coverage.dat`. |
| `mutants.py` | Regex mutants of the RTL (one operator or constant at a time, code only). No LLM involved. |
| `gate.py` | `verify()` / `verify_many()` (lint, port check, run suite) and `qualify()` (see below). CLI: `python -m ppa_opt.verify.gate verify\|qualify`. |
| `spec.py` | Parses the spec's `Top module:` line and port table; checks a suite's ports against it. |

**Oracle:** a cycle-accurate Python reference model plus optional SystemVerilog assertions, both written from the spec. Pass means no mismatch found by simulation; it is not a proof, and Verilator is two-state so X-propagation bugs are not seen.

**Failure classes.** Count against a candidate: `lint`, `interface`, `mismatch`, `assertion`. Do not count (candidate is unverified, not judged wrong): `build`, `suite`, `tool_crash`. Simulator crashes are retried once.

**Qualifying a suite** (`make qualify`): the suite must pass the first RTL, hit every spec cover point, reach line coverage of at least 90% and toggle of at least 80%, and kill at least 80% of mutants of that RTL. Verdicts: `qualified`, `suite_weak`, `rtl_suite_disagree` (RTL and suite read the spec differently; someone checks the spec, neither is blamed automatically), `suite_invalid`.

**Demo results (ALU, `examples/parallel_demo`, suite `suites/alu_p`):** v0–v3 pass; v4 (the deliberately wrong shared adder) fails on `lt`; v5 fails at lint. The SVA alone, with the model switched off, also fails v4 as an `assertion`. Qualification of `alu_p` against v0: 100% line and toggle, 8 of 8 mutants killed.

**Practical issues found and fixed**
- GNU make cannot build in a path with a space, and this project's path has one. Verification builds go under the system temp dir, and cocotb's lib/share dirs are reached through a symlink there.
- Verilator 5.052 has no `--xml-only`; ports come from `--json-only`, resolving type pointers by address.
- The cocotb runner builds the simulator's `PYTHONPATH` from `sys.path`, so the project root is inserted there.

## 2. Dev agents — `.claude/agents/`

| Agent | Input | Must not read |
|---|---|---|
| `spec-resolver` | informal description with no port table | RTL, `suites/` |
| `rtl-author` | resolved spec (and, in rewrite mode, current RTL plus critical-path summary) | `suites/` |
| `test-author` | resolved spec | any RTL |

The resolver writes `<name>.resolved.md` with a port table, behaviour, and an **Inferred decisions** list that a person should read: those choices (reset style, latency, widths) become the definition of "correct". `rtl-author` has a rewrite mode: same ports, cycle-exact, no added or removed registers.

Headless runner: `ppa_opt/llm/devagents.py` calls `claude -p --agent ...` (found on PATH, via `CLAUDE_BIN`, or in the VS Code extension bundle) with `--permission-mode acceptEdits` and read-denies (`suites/**` for the RTL author; `examples/**/*.sv`, `examples/**/*.v`, `work/**` for the test author). The denies are a guardrail: RTL stored elsewhere is not blocked, and Bash is limited to `.venv/bin/python` but could still read files. Production should replace this with direct API calls and a sandboxed verifier container; today the suite's Python runs unsandboxed on the host.

## 3. Make commands added

| Command | What it does |
|---|---|
| `make rtl SPEC=x.md [OUT=] [FORCE=1]` | resolver if the spec has no port table, then `rtl-author`; checks the RTL elaborates and its ports match. Refuses to overwrite without `FORCE=1`. |
| `make suite SPEC=x.md [OUT=] [FORCE=1]` | `test-author` writes `suites/<top>/`; static checks (loads, ports match, model runs a reset step, cover points exist). |
| `make suite-improve SPEC= SUITE= RTL= [ROUNDS=2]` | qualify; if `suite_weak`, send only the gaps (uncovered points, coverage, kinds of surviving mutants) back to `test-author`. No RTL text or line numbers. |
| `make qualify SUITE= RTL=` | qualify a suite against the first RTL. |
| `make verify SUITE= FILES="a.sv b.sv"` | gate candidates, verdict per file. |
| `make compare FILES=... SUITE=...` | gate, then measure only the passers (existing parallel runner). |
| `make ppa DESIGN=<name or path> [SUITE=]` | verify (if `SUITE`), then Yosys + OpenROAD flow and summary. Warns if no suite. |
| `make iterate SPEC= SUITE= RTL= CLOCK= [ITERS= N= KNOBS= BUDGET=]` | the iteration loop below. |

Spec arguments to `make rtl/suite` must currently be a path; accepting a bare name (`fp16_multiply.resolved`) was written but the edit was interrupted and is **not applied**.

## 4. Iteration loop — `ppa_opt/loop/iterate.py`

For a setup-slack violation: the target clock is a requirement; first drive slack to 0 or better, then minimize area while keeping timing met.

- **Critical path:** `ppa_opt/synth/timing.py` parses the worst setup path from OpenROAD's `6_finish.rpt` (start/end, slack, logic depth, cell histogram, slowest stages, provenance). `run_flow` stores it in the result as `critical_path`; a cache hit from before this existed falls back to reading the run directory, and the loop prints a note if neither is available.
- **Flow knobs** (new `FlowConfig` fields, left out of the cache key at their defaults so old cache entries stay valid): `synth_hierarchical`, `place_density_addon`, `setup_slack_margin`, `gpl_timing_driven`. `Candidate` gained an optional `cfg` override so knob variants go through `run_many`.
- **Each round:** N rewrites from `rtl-author` in parallel, each with a different strategy hint (balance trees, prefix adders, flatten muxes, precompute, duplicate fanout, move decode off the path; area hints once timing is met), plus flow-knob variants of the best RTL. Rewrites go through the suite; survivors are measured. Selection is a total order: timing met beats not met; among met, smaller area; among violating, higher slack. A design that breaks timing is never accepted.
- **Stops:** iteration limit; area gain under 2% for two rounds once timing is met; no slack improvement for two rounds; every rewrite rejected two rounds in a row; time budget. Exit code is 0 only if timing is met.
- **Output:** `work/iterations/<design>/iter_<k>/` (candidate RTL), `history.json` (metrics, provenance, gate status per candidate), `best.sv`. The user's RTL is never overwritten.
- **Limit by default:** rewrites are cycle-exact, so without `MAXLAT` the loop cannot add pipeline stages. If it stalls it says so and lists the options (see 4b for `MAXLAT`).

### 4b. Pipeline stages (added later in the session)
- `make iterate ... MAXLAT=N` (`--max-extra-latency`, default 0). Chosen policy: explicit per-run flag, and pipelining is tried only after cycle-exact rewrites stall (allowance rises one stage per stalled round, up to N; then half of each round's rewrites are pipelined via `rtl-author`'s "PIPELINE MODE").
- `ppa_opt/verify/latency.py` (`LatencyTracker`): one simulation compares the DUT output at cycle t with the model output at cycle t-k for every k in 0..N and reports the smallest k with no mismatch. After a reset the outputs are not checked for k+1 cycles (stages flushing).
- `gate.verify(..., max_extra_latency=N)` always runs the strict cycle-exact check first; only a mismatch or assertion failure triggers the tolerant run. SVA is omitted from the tolerant build because it assumes the original latency, so that check is weaker. `GateResult.latency_extra` carries the result; `make verify ... MAXLAT=N` exposes it.
- Selection: timing met beats violated; among met, lower added latency, then smaller area; once timing is met the latency is frozen. The final report warns that a design with added latency is not a drop-in replacement; `best.json` records it.
- A design that fails at every delay reports the first mismatch per delay tried (`+0: 'y' at cycle 5; +1: 'lt' at cycle 9`), because "which delay failed latest" is not a reliable guess at the intended one.
- To continue from a previous best without overwriting its history: `make iterate ... RTL=work/iterations/<design>/best.sv NAME=<new name>` (`NAME` was added to the make target for this).
- Tested with a hand-written 1-stage ALU (`tests/data/alu_p_pipe1.sv`): rejected strictly, accepted as +1 with an allowance (smallest k, not the limit), a buggy variant still rejected, a cycle-exact design stays at 0; loop escalation tested with fakes. Not yet run on a real flow (fp16_multiply with `MAXLAT=1` is the obvious test).

### 4d. Commenting requirement
`rtl-author` must start every file with a header comment (Strategy, What changed, Why it helps, Equivalence, Latency, Tradeoffs), comment every always/assign/generate/function/case block, and mark changed logic with `// OPT:`; no invented numbers. The iteration prompt repeats this. `iterate.comment_check()` flags missing headers or uncommented blocks per candidate (logged, saved as `doc_notes` in `history.json`); it never rejects, because correctness is the suite's job. Candidates from before this change (for example the three fp16_multiply rounds) are not documented this way.

### 4e. Runs continue from their folder
`make iterate` now treats `work/iterations/<name>/` as the run's memory. With an existing `history.json` + `best.sv`, it starts from that best design (copied to `iter_<k+1>/<top>_start.sv`, gated with the best's own latency, measured), numbers new rounds after the last one and appends to the same history; `RTL=` is only needed for a new run. It refuses a different `CLOCK` than the run's `best.json` records, and `FRESH=1` renames the old folder to `<name>.old-<timestamp>` instead of deleting it. Added after a second run into the same folder name overwrote the first run's three rounds in `history.json`; that lost history is not recoverable from the folder (the cache and run directories still hold the flow results).

### 4c. Report (`make viz`)
`ppa_opt/viz/report.py` + `template.html` build `work/report.html` from `work/iterations/*/history.json` (and `best.json`): a standalone page with a run selector, summary tiles (start vs best, with percentage change), four small-multiple charts by round (area, estimated power, critical-path delay with the target clock, added latency) showing every measured candidate as a dot and the best-so-far as a line, per-round chips (measured/rejected), and the candidates grouped into one drop-down per round (newest open, expand/collapse all) with the round's winner in the header and as a highlighted first row; a round with no improvement says so and grey-marks its strongest candidate; rejected candidates are listed last with the reason. Hover and keyboard focus show a tooltip; the table is the non-hover alternative. The target clock is derived as min period + setup slack, power is shown in mW. Styling follows the dataviz skill (one accent hue for the best design, grey for candidates, light and dark themes).
Checked: the data builder and rendering have unit tests (`tests/test_viz.py`), and the page script was executed in JavaScriptCore with a stub DOM against the real alu_p and fp16_multiply runs (4 charts, 5 tiles, 19 table rows, tooltip fires). The visual layout has not been inspected in a real browser.

## 5. Results of real runs

**ALU at 3.0 ns** (timing already met at +0.354 ns, so only the area phase ran): 2 rounds, 10 designs, none rejected. Best was a rewrite, 2397.3 → 2177.1 µm² (−9.2%) with +0.320 ns slack. Round 2 found nothing better. This did not exercise the timing phase.

**fp16_multiply at 5.0 ns** (your original run: setup slack −1.670 ns, hold +0.422 ns, 13033.8 µm², 346 s per flow). Suite qualified first: 100% line, 99% toggle, 23 of 24 mutants killed (the survivor is a constant change at line 40). Then `make iterate ... ITERS=3 N=4 KNOBS=2`:

| Round | Best | Slack (ns) | Area (µm²) |
|---|---|---|---|
| start | baseline | −1.670 | 13033.8 |
| 1 | r1c3 | −1.476 | 12474.5 |
| 2 | r2c1 | −1.015 | 13091.3 |
| 3 | r3c1 | −0.756 | 13277.7 |

All 18 candidates passed the suite. Timing was not met. Slack improved every round; area ended 1.9% above the baseline. The worst path went from 25 cells to 19, still five full adders in series (`b1[13]` → `pn2[19]`). The flow knobs changed slack by 0.001 ns or less on this design. Rewrite quality varied widely within a round (round 3: −2.13 to −0.76 ns). The design's minimum period is now about 5.76 ns.
